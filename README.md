- `data/site-content.js`: everything the admin edits. The site reads it on every page.
- `admin/store/content.json`: the admin's saved copy, with the last 30 versions in `admin/store/history/`. It can't be opened from the web.

## Putting it on the client's hosting (Apache with PHP 8.0 or newer, as WordPress already uses)

The admin was tested on 26 Oct 2026 with PHP 8.5: 35 checks covering login, lockout, CSRF, every editing page, input checks, escaping, blocked files, username and password changes, and save history.

1. Upload everything, including `admin/` and the `.htaccess` files.
2. **Set the admin login before going live.** On your computer, run `python 3d/demo2/tools/set_password.py <this folder> <username>`. It asks for the password twice and makes `admin/config.php`, which you then upload. The admin cannot be logged into until this file exists.
   - **After that, the client changes it themselves:** log in, open the **Login** tab, then change the username, the password, or both. They confirm with the current password; the new details work at the next login.
   - **Forgotten password:** whoever has hosting access runs the same script with a new password and uploads the new `config.php` over the old one. Nothing else is lost.
3. Make sure PHP can write to `data/` and `admin/store/` (folder permissions 755, or 775 if the host needs it).
4. Open `https://<domain>/admin/` and log in.

The admin only runs where PHP runs. On GitHub Pages leave `admin/` out: there it would be shown as plain files instead of running. The site itself works anywhere and reads `data/site-content.js` as it is.

## Security in the admin

- The password is stored only as a PBKDF2-SHA256 hash.
- After 5 wrong attempts from the same address, logins are blocked for 15 minutes.
- Sessions use secure, HTTP-only cookies and end after 30 minutes idle.
- Every form carries a CSRF token.
- On the live server the admin redirects to https.
- `lib.php`, `config.php` and `store/` are blocked from the web.
- All input is checked: links must be https, YouTube links must be real YouTube links, and the text written into the public file is escaped.

## Rebuilding

This folder is generated by `python 3d/demo2/build_demo2.py`. It runs the demo1 build (`3d/demo1`), which runs Site Lab 3 (`3d/lab3`) and draft 1 (`3d/draft-build`, sources in `3d/web`), then adds demo 2's changes.
